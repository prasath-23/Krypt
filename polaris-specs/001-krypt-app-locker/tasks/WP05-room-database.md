# WP05 - Data layer: Room database + entities + DAOs

## Objective

Define the Room schema for Krypt exactly as described in `data-model.md`. Four entities: `LockedApp`, `GuardianPairing`, `OutstandingRequest`, `UnlockGrant`. All DAOs expose suspend + `Flow<T>` query methods for coroutine-native access. Schema version 1; migrations strategy documented for future evolution.

## Context

- **Data model (authoritative):** `polaris-specs/001-krypt-app-locker/data-model.md` sections "Entity: LockedApp", "Entity: GuardianPairing", "Entity: OutstandingRequest", "Entity: UnlockGrant".
- **Spec FR-016:** "The system MUST provide an internal mock/seam for the locked-apps database" - achieved via repository abstractions in WP06.

## Subtasks

### T022 - LockedApp entity + DAO + enums

**Purpose.** First-class Room entity for the locked-apps table.

**Files to create:**
- `app/src/main/java/com/krypt/app/data/LockState.kt` (enum)
- `app/src/main/java/com/krypt/app/data/LockSource.kt` (enum)
- `app/src/main/java/com/krypt/app/data/LockedAppEntity.kt`
- `app/src/main/java/com/krypt/app/data/LockedAppDao.kt`

**Implementation steps:**
1. `LockState`: `LOCKED, UNLOCKED`. Persisted as TEXT via `@TypeConverter`.
2. `LockSource`: `DEFAULT_DENY, MANUAL`. Persisted as TEXT.
3. `LockedAppEntity` annotated `@Entity(tableName = "locked_apps")`, primary key `packageName: String`. Fields per data-model.md.
4. `LockedAppDao`:
   - `@Insert(onConflict = REPLACE) suspend fun insert(app: LockedAppEntity)`
   - `@Query("SELECT * FROM locked_apps WHERE packageName = :pkg") suspend fun findByPackage(pkg: String): LockedAppEntity?`
   - `@Query("SELECT * FROM locked_apps ORDER BY displayName") fun observeAll(): Flow<List<LockedAppEntity>>`
   - `@Query("UPDATE locked_apps SET lockState = :state, updatedAt = :ts WHERE packageName = :pkg") suspend fun updateLockState(pkg: String, state: LockState, ts: Long)`
   - `@Delete suspend fun delete(app: LockedAppEntity)`
5. Enum converters in a shared `Converters` class (created later in T026 alongside the DB class).

**Validation.** Schema diff under `app/schemas/com.krypt.app.data.KryptDatabase/1.json` matches expectation; generated by Room's `schemaLocation` annotation processor option in T026.

**Files to create:**

**Implementation steps:**
1. Entity PK `requestId: String`. Fields per data-model.md.
2. DAO:
   - `@Insert suspend fun insert(req: OutstandingRequestEntity)`
   - `@Query("SELECT * FROM outstanding_requests WHERE requestId = :id") suspend fun findById(id: String): OutstandingRequestEntity?`

## Test Strategy

- **Unit (JVM):** none (Room requires SQLite runtime).
- **Instrumented (androidTest):** T026 `KryptDatabaseTest` covers all DAOs + the atomic-consume race.
- **Schema guard:** schema JSON checked into VCS; a future migration PR that changes schema without bumping `version` + adding a `Migration` object will fail Room codegen.

## Risks + Edge cases

- **KSP vs kapt.** Room 2.6.1 supports KSP; Hilt 2.52 still defaults to kapt. Mixing generates one-time warnings. Pick kapt for both (Hilt compat) OR Room KSP + Hilt kapt; document choice.
- **Schema JSON in VCS.** Merge conflicts on `1.json` during parallel WP05 + WP06 development. Hold WP06 off from modifying the schema; WP06 only adds repositories, no new columns.
- **ByteArray equals() in entities.** Room-generated `equals`/`hashCode` on `ByteArray` fields compare by reference, not content. For tests, use the entity in `assertEquals(expected.copy(pubSalt = received.pubSalt), received)` pattern, or override `equals`/`hashCode` manually. Manual is cleanest.
- **Single-row enforcement for `guardian_pairing`.** We enforce via `PK id = 1`; a developer bug that inserts with id=2 would succeed. Consider a `CHECK(id = 1)` table constraint via `@Entity(tableName = "...", indices = [...], /* no check-constraint support in Room pre-2.7 */)`. Alternative: wrap DAO to reject non-1 ids.
- **Atomic `markConsumedIfOpen` and SQLite isolation.** Room uses WAL mode by default. The UPDATE with WHERE clause is atomic within a single transaction; two parallel calls cannot both see `consumed = 0`. Test must actually be concurrent (dispatchers.IO + `async`) not sequential, to catch a regression.
