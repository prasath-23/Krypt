# /polaris.runtests - Run Tests with Auto Lane Transitions

**Version**: 2026.3.0+
**Purpose**: Execute tests for work packages and automatically transition lanes based on results. Supports both project test suites (unit/integration) and E2E browser tests.

## Test Modes

This command supports two test modes:

| Mode | What it runs | Runner | When to use |
|------|-------------|--------|-------------|
| **Project tests** (default) | Unit/integration tests via detected framework | `run_tests.py` (pytest, npm test, cargo test, go test) | After implementation, before review |
| **E2E browser tests** | Browser-based end-to-end tests from `.spec.js` files | `agent-browser` or `playwright` | After project tests pass, for UI validation |

## Lane Transition Flow

```
doing -> testing -> for_review   (tests pass)
doing -> testing -> doing        (tests fail, with failure details)
```

When tests start, the WP moves to `testing` lane. On pass, it moves to `for_review`. On fail, it moves back to `doing` with failure details appended to the activity log.

## Usage

```bash
# Run project test suite (unit/integration - default mode)
polaris runtests
polaris runtests --wp WP01

# Validate test plan coverage (requires test-plan.md from /polaris.autopilot or manual creation)
polaris runtests --validate-plan

# Run E2E browser tests
polaris runtests --mode e2e
polaris runtests --mode e2e --runner playwright

# Specify feature
polaris runtests --feature 001-my-feature

# Run ALL tests across ALL features (regression mode)
polaris runtests --all

# Run E2E in headed mode (see browser)
polaris runtests --mode e2e --headed
```

## Project Test Suite (Default Mode)

Runs the project's unit and integration tests using the auto-detected framework.

### How it works

1. Detects the test framework from project config files:
   - `pyproject.toml` / `setup.py` / `setup.cfg` -> `python -m pytest`
   - `package.json` -> `npm test`
   - `Cargo.toml` -> `cargo test`
   - `go.mod` -> `go test ./...`
2. Executes tests via `.polaris/scripts/tasks/run_tests.py`
3. Parses structured JSON results (passed/failed/skipped/errors)
4. Transitions WP lanes based on results

### Direct execution

You can also run the test script directly:

```bash
# Run all project tests
python .polaris/scripts/tasks/run_tests.py --project-root . --json

# Filter by work package (pytest -k filter)
python .polaris/scripts/tasks/run_tests.py --project-root . --wp WP01 --json

# Run only tests for a specific feature (tests/<slug>/ directory)
python .polaris/scripts/tasks/run_tests.py --project-root . --feature 001-my-feature --json

# Validate test plan coverage (>= 80% required)
python .polaris/scripts/tasks/run_tests.py --project-root . --validate-plan polaris-specs/<slug>/test-plan.md --json
```

### JSON output format

```json
{
  "framework": "pytest",
  "command": "python -m pytest",
  "exit_code": 0,
  "passed": 12,
  "failed": 0,
  "skipped": 1,
  "errors": 0,
  "total": 13,
  "duration_seconds": 3.45,
  "output": "...",
  "success": true,
  "validation": {
    "planned": ["test_create_user", "test_delete_user"],
    "found": ["test_create_user", "test_delete_user"],
    "missing": [],
    "coverage_percent": 100.0
  }
}
```

The `validation` object is only present when `--validate-plan` is used.

### Test plan validation

If a test plan exists at `polaris-specs/<slug>/test-plan.md` (created during `/polaris.autopilot` Stage 2c or manually), you can validate that all planned tests are implemented:

- Extracts `test_*` names from the test plan markdown
- Scans project source for matching `def test_*` function definitions
- Reports coverage percentage and lists any missing tests
- **Gate**: Autopilot requires >= 80% coverage before proceeding to review

## E2E Browser Tests (`--mode e2e`)

Runs browser-based end-to-end tests from `.spec.js` files generated by `/polaris.tasks`.

### Available E2E Runners

| Runner | How it works | Description |
|--------|--------------|-------------|
| `agent-browser` | Parses .spec.js comments, drives `npx agent-browser` command-by-command | Browser automation via CLI orchestration (default) |
| `playwright` | `npx playwright test` | Standard Playwright E2E tests |

The agent-browser runner parses test instructions from `//` comments in .spec.js files and translates them into agent-browser CLI calls (open, click, fill, snapshot, etc.). API-only tests (fixture type `request`) use Python HTTP calls instead of a browser.

If the default runner is unavailable, the command automatically falls back to the other.

### E2E Test File Structure

Tests are generated by `/polaris.tasks` under:
```
polaris-specs/{feature}/tests/
  e2e/
    WP01-{slug}.spec.js
    WP02-{slug}.spec.js
  e2e-tests.md           # Human-readable test plan
```

Each WP's frontmatter includes:
- `test_status`: `pending | running | passed | failed | skipped`
- `test_file`: relative path to the test spec file

## When to Use

**After implementation, before review:**
```
/polaris.specify -> /polaris.tasks -> /polaris.implement -> /polaris.runtests -> /polaris.review
```

Run `/polaris.runtests` after implementing a WP to validate it before sending to review. This replaces the manual `move-task --to for_review` step - tests handle the lane transition automatically.

**Recommended sequence:**
1. Run project tests first (default mode) to validate logic
2. Run E2E tests (`--mode e2e`) to validate UI behavior
3. Both must pass before review

## Options

| Option | Default | Description |
|--------|---------|-------------|
| `--mode` | `project` | Test mode: `project` (unit/integration) or `e2e` (browser) |
| `--runner, -r` | `agent-browser` | E2E test runner: `agent-browser` or `playwright` (only for `--mode e2e`) |
| `--feature, -f` | auto-detected | Feature slug. Runs only tests in `tests/<slug>/` directory; falls back to full suite if directory not found |
| `--wp` | all eligible | Specific WP to test |
| `--validate-plan` | `false` | Also validate test plan coverage (project mode only) |
| `--all` | `false` | Run ALL tests across all features (regression mode, no lane changes) |
| `--headed/--headless` | `--headless` | Browser visibility mode (E2E mode only) |
| `--base-url` | `http://localhost:5173` | Frontend base URL for agent-browser (E2E mode only) |
| `--api-url` | `http://localhost:8000` | API base URL for API tests (E2E mode only) |

## Troubleshooting

**"No test framework detected"**
- Ensure your project has `pyproject.toml`, `package.json`, `Cargo.toml`, or `go.mod` in the project root.
- The test runner auto-detects the framework from these config files.

**"No test files found" (E2E mode)**
- Run `/polaris.tasks` first - it generates E2E test skeletons alongside work packages.

**"No work packages eligible for testing"**
- Only WPs in `doing` or `testing` lanes are tested by default.
- Use `--wp WP01` to test a specific WP regardless of lane.

**"run_tests.py not found"**
- Run `polaris upgrade` to deploy the test runner script to `.polaris/scripts/tasks/`.
- Or check that `.polaris/scripts/tasks/run_tests.py` exists in your project.

**"agent-browser is not available"**
- Install: `npm install -g @anthropic-ai/agent-browser`
- Or use Playwright: `polaris runtests --mode e2e --runner playwright`

**"playwright is not available"**
- Install: `npm init playwright@latest`
- Or use agent-browser: `polaris runtests --mode e2e --runner agent-browser`

## Failure Classification

After running tests, classify each failure to determine the appropriate response. Use `specify_cli.testing.failure_classifier` for programmatic classification or apply these rules manually:

### Classification Categories

| Category | Pattern Matches | Action |
|----------|----------------|--------|
| **environment** | `connection refused`, `port in use`, `ModuleNotFoundError`, `FileNotFoundError`, `PermissionError`, `command not found`, `ECONNREFUSED`, `EADDRINUSE` | Auto-retry once after 2s delay |
| **flaky** | Test passes on retry after initial failure | Tag with retry count, mark as resolved |
| **stale-selector** | `element not found`, `no such element`, `waiting for selector`, `locator` | Report for self-healing (do not retry) |
| **genuine** | All other failures, or consistent failure on retry | Report with full error details |

### Auto-Retry Workflow

1. On first failure, classify the error message against the patterns above.
2. If **environment**: wait 2 seconds, then retry the test once.
3. For all other failures: retry once to detect flakiness.
4. If the test **passes on retry**: reclassify as **flaky** with `resolved=True`.
5. If the test **fails again**: keep original classification with `resolved=False`.
6. **stale-selector** failures skip retry and are flagged for self-healing in regression mode.

### Classification Summary Output

After all tests complete, display a summary grouped by category:

```
Failure Classification Summary
-------------------------------
genuine (2):     test_calculate_total, test_validate_input
environment (1): test_api_connection  [retried, still failing]
flaky (1):       test_race_condition  [resolved on retry]
stale-selector (0): (none)
```

### Programmatic Usage

```python
from specify_cli.testing.failure_classifier import (
    classify_failure,
    should_retry,
    get_retry_delay,
    format_failures_markdown,
)

classification = classify_failure("test_api", "ConnectionRefusedError: ...")
if should_retry(classification):
    delay = get_retry_delay(classification)
    # wait delay seconds, then re-run the test
```

## Regression Testing

Use `--all` to run tests across ALL features in the project. This is useful for validating that new changes haven't broken existing features.

```bash
# Run all project tests across all features
polaris runtests --all

# Run all E2E tests across all features
polaris runtests --all --mode e2e

# Regression with specific runner
polaris runtests --all --mode e2e --runner playwright
```

**Regression mode behavior:**
- Project mode: Runs the full project test suite once (not per-feature)
- E2E mode: Scans `polaris-specs/*/tests/e2e/*.spec.js` for all features
- Runs every test regardless of WP lane status
- Does NOT change any lanes (read-only mode)
- Reports results with a summary table
- Exits 0 if all pass, 1 if any fail
